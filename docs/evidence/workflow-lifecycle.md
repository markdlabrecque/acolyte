# Workflow lifecycle evidence

Group A implements the injected `runTicket` lifecycle and its three role prompts. The controller records an effect marker before implementation, checks, review, publication and merge; retains review history and check failures; consumes at most two repairs; and checks clean, unchanged HEAD around approval, publication and merge. Only a confirmed merge result records `merged`. Interrupted stages other than `waiting-ci` stop for human inspection; an interrupted merge is never replayed automatically. A waiting-CI record requires a matching last approval and PR before resuming.

Synthetic injected-port tests cover complete execution, repair exhaustion, check failures, rejection history, stale review and HEAD movement, dirty trees, uncertain effects and restart. `npm test` passed 167 tests, `npm run typecheck` and `git diff --check` passed. The first test attempt failed because dependencies were absent; they were installed from the local npm cache with `npm_config_userconfig=/dev/null npm ci --offline --ignore-scripts --no-audit --no-fund` before rerunning. No real credentials or live model calls were used.

Integration remains necessary: the caller must hold an exclusive per-issue reservation, use `reserved` for a newly dispatched record, and supply durable storage and trusted ports that enforce sandboxing, fresh independent verification and the CI merge gate. This note does not establish independent review, remote CI, provider model access, operational authorization or TD-002 live acceptance. Test execution here used the trusted local candidate, not agent-produced code.
